# 日历价格前端接口文档

## 文档说明

本文档**专门**描述日历价格库存表 `goods_daily_calendar` 的相关接口字段与使用方式。

### 设计前提

- 日历价格**没有独立的添加/编辑接口**，操作完全整合在以下 3 个商品接口中：

| 接口 | 路径 | 日历字段作用 |
|:---|:---|:---|
| 商家编辑商品 | `POST /api/user/shop/goods/edit` | 提交日历价库存（按需配置） |
| 商家商品详情 | `POST /api/user/shop/goods/detail` | 回显日历价库存（编辑页回填） |
| 公开商品详情 | `GET/POST /api/shop/goods/detail` | C 端展示日历价库存（按日期下单） |

### 适用业态

- `GoodsProduct.StockType = 2`（每日/场次动态库存）的商品，**主要是酒店（HOTEL）和景区（TOUR）**，用于支持"平时价 / 周末价 / 节假日价"差异化定价。
- 普通业态（餐饮/娱乐等 `StockType=1`）可不配置日历，按总库存售卖即可。

### 三元唯一约束

- `(product_id, sku_id, date)` 三字段联合唯一：同一 SKU 同一日期仅允许一条记录。
- `sku_id = 0` 表示**商品维度**的日历（无规格商品使用）；`sku_id > 0` 表示**具体 SKU 维度**的日历（有规格商品按规格分别配置）。

## 一、calendar 数据结构

### 1.1 calendar[].Object 字段表

| 参数名 | 必选 | 类型 | 说明 |
|:---|:---:|:---:|:---|
| sku_id | 否 | int64 | 关联 SKU ID，`0` 表示商品维度（无规格商品）；有规格商品按 SKU 分别设置 |
| date | 是 | string | 日期，格式 `YYYY-MM-DD`（如 `2026-10-01`）；后端会按日期部分写入 |
| price | 是 | number | 当日售价（元），如周末 598、平时 398、节假日 888 |
| stock | 是 | int | 当日库存，售完为 `0` |
| status | 否 | int | `1`-可售（默认）；`0`-停售/闭店/闭园，前端不可下单 |

> 字段 `id` / `product_id` / `createtime` / `updatetime` 由后端自动维护，前端提交时**可忽略**（编辑接口会强制重置 `id=0`，并按商品 ID 自动关联）。

### 1.2 三语义编辑规则（关键）

编辑商品接口对 `calendar` 字段采用统一的附表三语义：

| 传值方式 | 行为 |
|:---|:---|
| 不传字段 / 传 `null` | **保留**原日历数据不动 |
| 传 `[]`（空数组） | **清空**该商品所有日历记录 |
| 传非空数组 | **全量重建**（先删该商品所有旧日历，再按数组插入新记录） |

> ⚠️ 因此前端若只想改主表/SKU 等信息，**不要带 `calendar` 字段**；若要修改日历，需把**完整的最终日历列表**传过来（不是增量）。例如：要给 10 月新增 1 天，需要传完整的 10 月所有日期记录（含已存在和新增的）。

### 1.3 完整 JSON 示例

```json
[
  { "sku_id": 7, "date": "2026-10-01", "price": 598, "stock": 10, "status": 1 },
  { "sku_id": 7, "date": "2026-10-02", "price": 598, "stock": 8,  "status": 1 },
  { "sku_id": 7, "date": "2026-10-03", "price": 698, "stock": 0,  "status": 0 },
  { "sku_id": 7, "date": "2026-10-04", "price": 398, "stock": 20, "status": 1 }
]
```

## 二、提交日历价：商家编辑商品接口

**请求URL：** `POST /api/user/shop/goods/edit`

**请求头：** 需携带商家/店长登录 Token，字段名 `pgtoken`（也兼容 `Authorization: Bearer <token>`）

### 2.1 calendar 字段参数表（与主商品字段并列）

| 参数名 | 必选 | 类型 | 说明 |
|:---|:---:|:---:|:---|
| id | 是 | int64 | 商品 ID |
| shop_id | 是 | int64 | 所属店铺 ID |
| ... | ... | ... | 其余主表字段见[商家编辑团购商品接口文档](./商家编辑团购商品接口文档.md) |
| calendar | 否 | array\<Object\> | 日历价库存；**三语义**（见 1.2） |

### 2.2 请求示例（仅展示 calendar 部分，需嵌入完整编辑请求体）

```json
{
  "id": 3,
  "shop_id": 1,
  "title": "海景大床房晚（含双早）",
  "biz_type": "HOTEL",
  "product_type": "ROOM_NIGHT",
  "selling_price": 398,
  "stock_type": 2,
  "total_stock": 0,
  "skus": [
    { "sku_name": "大床房", "price": 398, "stock": 20 }
  ],
  "calendar": [
    { "sku_id": 7, "date": "2026-10-01", "price": 598, "stock": 10, "status": 1 },
    { "sku_id": 7, "date": "2026-10-02", "price": 598, "stock": 8,  "status": 1 },
    { "sku_id": 7, "date": "2026-10-03", "price": 698, "stock": 0,  "status": 0 },
    { "sku_id": 7, "date": "2026-10-04", "price": 398, "stock": 20, "status": 1 }
  ]
}
```

### 2.3 返回示例

```json
{
  "code": 200,
  "message": "编辑团购商品成功",
  "data": { "id": 3, "updated": 1 }
}
```

### 2.4 常见错误

| code | 触发条件 |
|:---:|:---|
| 401 | 未登录 / Token 失效 |
| 403 | 越权（商品不属于当前商户） |
| 404 | 商品不存在 |
| 500 | 服务器错误（事务回滚） |

## 三、回显日历价：商家商品详情接口

**请求URL：** `POST /api/user/shop/goods/detail`

**请求头：** 需携带 pgtoken

### 3.1 请求参数

| 参数名 | 必选 | 类型 | 说明 |
|:---|:---:|:---:|:---|
| id | 是 | int64 | 商品 ID |
| shop_id | 否 | int64 | 店铺 ID；传了则一并校验归属 |

### 3.2 返回的 calendar 字段（位于 data.calendar）

| 参数名 | 类型 | 说明 |
|:---|:---:|:---|
| data.calendar | array | 该商品所有日历记录，原样返回（含 `status=0` 停售记录），按 `date` 升序；无记录返回 `[]` |

**calendar[] 返回字段：**

| 字段 | 类型 | 说明 |
|:---|:---:|:---|
| id | int64 | 主键 ID |
| product_id | int64 | 关联商品 ID |
| sku_id | int64 | 关联 SKU ID，`0` 为商品维度 |
| date | string | 日期（ISO 时间格式，如 `2026-10-01T00:00:00+08:00`，前端用 `date.slice(0,10)` 取日期部分） |
| price | number | 当日售价（元） |
| stock | int | 当日库存 |
| status | int | `1`-可售；`0`-停售/闭店/闭园 |
| createtime | string | 创建时间 |
| updatetime | string | 更新时间 |

### 3.3 返回示例（仅展示 calendar 部分）

```json
{
  "code": 200,
  "message": "获取成功",
  "data": {
    "product": { "...": "主表字段" },
    "skus":     [ /* SKU 列表 */ ],
    "calendar": [
      { "id": 1, "product_id": 3, "sku_id": 7, "date": "2026-10-01T00:00:00+08:00", "price": 598, "stock": 10, "status": 1, "createtime": "...", "updatetime": "..." },
      { "id": 2, "product_id": 3, "sku_id": 7, "date": "2026-10-02T00:00:00+08:00", "price": 598, "stock": 8,  "status": 1, "createtime": "...", "updatetime": "..." }
    ]
  }
}
```

## 四、C 端展示日历价：公开商品详情接口

**请求URL：** `GET/POST /api/shop/goods/detail`（无需登录）

### 4.1 请求参数

| 参数名 | 必选 | 类型 | 说明 |
|:---|:---:|:---:|:---|
| id | 是 | int64 | 商品 ID |

### 4.2 返回的 calendar 字段

| 参数名 | 类型 | 说明 |
|:---|:---:|:---|
| data.calendar | array | 该商品全部日历记录，按 `date` 升序；无记录返回 `[]` |

> ⚠️ 公开接口**不过滤** `status=0` 的日历记录（前端需自行屏蔽停售日），目的是让 C 端日历组件能正确显示"该日不可售"状态，而不是看起来像没有这天数据。

### 4.3 返回示例（仅展示 calendar 部分）

```json
{
  "code": 200,
  "message": "获取成功",
  "data": {
    "product": { "...": "主表字段", "stock_type": 2, "selling_price": 398 },
    "skus":     [ /* 启用的 SKU */ ],
    "calendar": [
      { "id": 1, "product_id": 3, "sku_id": 7, "date": "2026-10-01T00:00:00+08:00", "price": 598, "stock": 10, "status": 1 },
      { "id": 2, "product_id": 3, "sku_id": 7, "date": "2026-10-02T00:00:00+08:00", "price": 598, "stock": 8,  "status": 1 },
      { "id": 3, "product_id": 3, "sku_id": 7, "date": "2026-10-03T00:00:00+08:00", "price": 698, "stock": 0,  "status": 0 }
    ],
    "shop": { "...": "商家摘要" }
  }
}
```

## 五、未命中回落策略（C 端下单关键逻辑）

当 C 端用户选了某天，但 `calendar` 数组中**没有该日期的记录**时，按以下规则回落计价和库存：

| 字段 | 回落规则 |
|:---|:---|
| 价格 | 回落到 `GoodsProduct.SellingPrice`（商品主售卖价） |
| 库存 | 回落到 `GoodsProduct.TotalStock`（总库存）；若主表为 0，再看 SKU 的 `GoodsSku.Stock` |
| 可售状态 | 默认可售（视同 `status=1`） |

### 5.1 业务含义

- **商家不需要把所有日期都配日历价**：可以只配节假日/周末差异化定价，平时不配即回落默认价。
- **风险控制建议**：前端编辑页若某商品 `stock_type=2` 但日历未配任何记录，应给出明显的"未配置日历价将按默认价售卖"提示，避免商家漏配。
- **后端防御性校验**：若日历记录的 `price <= 0`，下单接口应拒绝（防止 0 元订单）。

### 5.2 前端日历组件匹配逻辑伪代码

```javascript
function getDayPriceStock(calendar, skuId, dateStr /* 'YYYY-MM-DD' */) {
  const hit = calendar.find(c => c.sku_id === skuId && c.date.slice(0, 10) === dateStr);
  if (hit) {
    return { price: hit.price, stock: hit.stock, sellable: hit.status === 1, fromCalendar: true };
  }
  // 未命中：回落到商品主售卖价 / 主表或SKU库存
  return { price: product.selling_price, stock: getTotalStockFallback(), sellable: true, fromCalendar: false };
}
```

## 六、典型业务流程

### 6.1 商家配置日历价流程

1. 调 `POST /api/user/shop/goods/list` 拿到商品列表，定位目标商品 ID。
2. 调 `POST /api/user/shop/goods/detail` 拉取商品完整数据（含已有 `calendar`），回填到编辑表单。
3. 用户在日历组件上选日期、设价格/库存/可售状态，前端组装成 `calendar` 数组。
4. 调 `POST /api/user/shop/goods/edit` 提交，`calendar` 字段传**完整最终列表**（不是增量）。

### 6.2 C 端选日期下单流程

1. 调 `GET/POST /api/shop/goods/detail?id=xxx` 拿到商品详情 + `calendar` 数组。
2. 前端日历组件按 `calendar` 渲染每个日期的价格/库存/停售状态。
3. 用户选中某日 → 匹配 `calendar` 命中或按未命中回落策略计算价格/库存 → 调下单接口。
